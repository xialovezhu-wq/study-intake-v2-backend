# Native Luna Parallel Contract

This contract applies only to native Codex child agents spawned by a Sol parent. It does not apply to the math, 408, or English background Study Intake Provider/MCP pipelines. Never start, poll, modify, or use those background pipelines merely to satisfy this contract.

## Eligibility

Spawn only when at least two workflows are independent, independently acceptable, and likely to improve elapsed time or quality. One short workflow stays with Sol. Split by natural outcome, evidence group, system, candidate shard, or independent test set rather than arbitrary file counts.

## Runtime identity

Use `fork_turns="none"` and one of the locally pinned native roles:

- `explorer`: read-only evidence and QA;
- `worker`: only an explicit, exclusive, non-overlapping path set;
- `default` or `luna_worker`: bounded general leaf work.

Each child must be a leaf. Available execution metadata must confirm `model=gpt-5.6-luna`, `model_reasoning_effort=max`, and `service_tier=fast`. Parent Sol Standard or Fast remains independent. If any identity field drifts or cannot be verified, discard the result and perform the work safely in Sol; do not change the parent tier to compensate.

## Task envelope

Every child receives all of the following:

1. objective and independently checkable deliverable;
2. exact input and evidence boundary;
3. read-only scope or one exclusive write-path set;
4. required return schema;
5. acceptance command or evidence check;
6. stop condition;
7. an explicit prohibition on further delegation.

## Fan-out, waves, and barrier

Use one child per eligible natural workflow. There is no Skill-level fixed child-count ceiling. Runtime concurrency remains finite and is controlled by Codex slots and service limits; start what fits, queue the remainder in waves, and track every workflow to one terminal result.

Wait at one fan-in barrier after all required children finish. Sol rejects wrong-scope, wrong-hash, mutation, incomplete, or unverified-runtime results; resolves conflicts; and performs final validation. Do not use peer voting or repeated critique rounds unless the owning Skill explicitly requires a separate post-artifact QA pass.

## Single-writer boundary

Sol owns architecture, approval, shared state, locks, receipts, IDs, formal transactions, conflicting paths, cross-shard deduplication, final assembly, and final acceptance. Parallel writes are allowed only when workers own mutually exclusive files and no shared index or transaction is touched. The same file, ledger, receipt, formal repository transaction, or ID namespace always has one writer.
